# QR Code Generation & Security

This document details the implementation of QR code generation for event passes, as implemented in task **8.3 – QR Code Generation and Embedding**.

## Overview

Instead of encoding a plain JSON object into the QR code, we now use a **signed JSON Web Token (JWT)**. This provides two key benefits:

1.  **Integrity**: The token is signed with a secret key (`JWT_QR_CODE_SECRET`). The check-in application can verify the signature to ensure the QR code was generated by our system and has not been tampered with.
2.  **Verifiability**: The payload contains all the necessary information for a check-in scanner to validate a guest's pass, potentially even in an offline scenario.

## Implementation Details

### 1. JWT Generation

- The `JwtService` (`apps/backend/src/auth/services/jwt.service.ts`) has been enhanced with a `generateQrCodeToken` method.
- This method signs a specific payload using a dedicated secret (`JWT_QR_CODE_SECRET`) and sets an expiration (`JWT_QR_CODE_EXPIRATION`), which is configurable via environment variables.

### 2. Service Integration

- `PdfPassService` now injects `JwtService`.
- When generating a pass, it creates the QR code payload and calls `generateQrCodeToken` to get the secure token string.
- This token string is then passed to the `qrcode` library to be rendered as a QR image.

### 3. QR Code JWT Payload

The JWT payload embedded in the QR code contains the following claims:

| Claim     | Type   | Description                                           | Example                                  |
|-----------|--------|-------------------------------------------------------|------------------------------------------|
| `eventId` | string | The UUID of the event.                                | `a1b2c3d4-e5f6-7890-1234-567890abcdef`   |
| `guestId` | string | The UUID of the guest.                                | `b2c3d4e5-f6a7-8901-2345-67890abcdef1`   |
| `passId`  | string | A unique identifier for this specific pass instance.  | `a1b2c3d4...-b2c3d4e5...-1672531200000`  |
| `iat`     | number | *Issued At* timestamp (automatically added by JWT).   | `1672531200`                             |
| `exp`     | number | *Expiration* timestamp (automatically added by JWT).  | `1704067200`                             |

### 4. Configuration

The following environment variables must be set:

- `JWT_QR_CODE_SECRET`: A long, random, and secret string for signing the tokens.
- `JWT_QR_CODE_EXPIRATION`: The token's lifespan (e.g., `365d`, `8h`). It should be long enough to last until the event is over.

## Verification (Future Task)

The check-in application (frontend/backend) will need to be updated to handle these JWT-based QR codes. The verification flow will be:

1.  Scan the QR code to get the token string.
2.  Call a verification endpoint or use a local library with the public key/secret to verify the token's signature and expiration.
3.  If valid, extract the `eventId` and `guestId` from the payload to proceed with the check-in process.
